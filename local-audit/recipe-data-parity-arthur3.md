# Recipe data restoration for Arthur .3

The official `TConstruct-1.20.1-3.12.1.231.jar` contains three recipes whose corresponding behavior was absent from the port's generated data: one honey block supplies four honey material units, 50 mB of blazing blood converts earthslime material into magma at temperature 1500, and bacon repairs a tasty tool in a crafting grid for 25 durability per modifier level before repair factors. Existing honey bottle, magma cream, and station repair recipes remain unchanged. The restored files use target ingredient syntax and the existing target serializers. The magma recipe retains the original `tconstruct:blazing_blood` tag, including datapack additions to that tag.

The converted optional ore-melting recipes also had a selection error. The original `forge:conditional` wrapper selects the first eligible byproduct. Splitting its alternatives into separately conditioned recipes allowed multiple alternatives to load together. Later branches now require every earlier optional byproduct tag to be empty. This also applies to the no-byproduct fallback. The datagen helper must emit the same mutually exclusive conditions to preserve this behavior after regeneration.

`optional_melting_branches.py` checks every generated recipe ending in `_byproduct_N` or `_fallback` against its matching ordered recipe in the pinned official archive. There are 61 families and 124 branch files; 63 later/fallback files required condition changes. All 124 branches retain their full current payload, including ingredient and recipe identity. Their result, byproduct amounts, ore rates, temperature, and time also match the original after the common-tag namespace migration. No balance adjustment was made.

`optional-melting-branch-validation.json` records the archive hash, every path, payload hashes, original eligibility, corrected conditions, and all 252 truth-table cases. Each possible byproduct-ingot tag-presence combination is tested with the common outer condition both false and true. This proves that exactly the original first branch is selected, or none when the outer condition fails. Outer ingredient tag intersections and exclusions are unchanged; this static check does not simulate tag contents or world melting.

Run `python local-audit/optional_melting_branches.py --report` from this project to repeat validation without changing recipes. The retained official archive is required; it is ignored by Git. `--apply` is an explicit, idempotent repair mode that changes only `neoforge:conditions` after verifying the expected prior shape and all recipe amounts. The frozen baseline audit is not rewritten.

Target NeoForge 26.1.2.109 provides `NotCondition(ICondition value)`, serialized as `{"type":"neoforge:not","value":...}`. Its predicate negates the contained condition. Condition arrays require every predicate to pass. The dedicated regression fixture exercises shipped JSON through registered target condition and recipe codecs; compilation and execution are coordinated by the parent task and remain pending for this batch.

This restoration does not establish complete recipe or rendering parity. Goat horn variants and their instrument ingredient are separately owned by the parent task. Optional kiln integration, entity-arrow tagging, command preset resources, external-mod equipment, remaining sprites, and other baseline omissions still need individual classification. No client, server, GUI, build, or world test was launched by this audit agent.
