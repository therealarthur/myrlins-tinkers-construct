# Armor and material parity plan

Comparison baseline: official `TConstruct-1.20.1-3.12.1.231.jar` and matching sources archive in `local-audit/upstream`, read as ZIP streams. Port baseline is Continuum main `72602856c8403c51f9f488ab1580f1216fa42fda`, followed by the local .1 compatibility checkpoint. The target runtime is Minecraft 26.1.2 / NeoForge 26.1.2.109. Original recipe paths use `recipes`; the target uses `recipe`. Registry names, attribute operations, ingredient codecs and conditions must use target APIs.

## Findings and patch ownership

| Area | Verified difference | Patch scope / preservation rule |
| --- | --- | --- |
| Sky and ender skin | Original has independent `skyslimeskin` / `enderslimeskin` definitions with cuirass and maille stats. Port uses `skyslime_vine#slimeskin` / `enderslime_vine#slimeskin`, so the appearance/acquisition exists but its traits share vine semantics. Original skin traits are airborn + overslime_friend / enderclearance + overslime_friend. | Add original IDs, material definition/stats/traits, acquisition and render information. Do not globally redirect vines, because actual vine laces/bindings must remain vines. |
| Venom material | Original has noncraftable tier 2, sort 30; slime durability 225, overslime capacity 0; magic_protection trait. Port has venom fluid/modifier but no material. | Add the material triplet, spider-eye value 1 and fermented-eye value 2 recipes, casting/melting at 250 mB, render information. |
| Cuirass and laces | Wool lacks cuirass/armor knockback resistance. Vine, weeping vine and twisting vine lack original cuirass stats. Leather laces use snow_boots instead of rugged. Source ownership: this track owns material IDs/providers and matching generated material resources; armor portions of ToolDefinitionDataProvider and tool-definition JSON; new RemappingMaterialsModule and index/value swapping classes; affected ToolsRecipeProvider/builder code. Shared reserved sections are TinkerTools loader registration, TinkerTables serializer registration, ModifierIds/ModifierProvider airborn and rugged, TinkerTags and DamageTypeTagProvider rugged tags. Existing MaterialSwappingRecipe base and .1 fixtures are not owned here. Viewer display integration is coordinated with the viewer track.

## Exact mechanism references

- Original `library/tools/definition/module/material/RemappingMaterialsModule.java`: remapping fills missing slots and replaces a mapped existing material at the same index. The default `MissingMaterialsToolHook.needsMaterials` only checks a short array. Port `ToolStack.ensureHasData` likewise calls this hook only for missing/short material arrays or missing initialization; complete old arrays do not enter remapping.
- Original `tools/data/ToolDefinitionDataProvider.java`, slimesuit section: primary part selects the rebalance trait; material trait module at slot 0 selects trim. Chestplate deliberately adds its ribcage trait twice through TOOL_TRAITS and the ordinary materials module.
- Original `library/recipe/tinkerstation/building/MaterialIndexSwappingRecipe.java`: choose first configured index unless the matching input is located at another configured index, validate material supports that stat, then delegate to the existing validated copy-and-swap path.
- Original `MaterialValueSwappingRecipe.java`: MaterialRecipeCache supplies material value, item count and leftovers; cost is also the part repair value. Its source returns false after successful shrink, although the base updateInputs loop only stops on true. The port must stop after the chosen input to avoid consuming multiple material stacks; actual transaction tests are required.
- Original `data/tconstruct/recipes/tools/armor/travelers/*_cuirass.json` and `shield_wood.json`: original costs and indices above. Existing casting swaps remain alongside station swaps.
- Original rugged damage tags: terrain = hot_floor, cactus, sweet_berry_bush, stalagmite, tconstruct:knightmetal (+ optional Twilight Forest knightmetal/fiery); level 2 attacks = cramming, sting, thorns (+ optional Twilight Forest thorns). It also sets the existing snow_boots volatile flag. Airborn is distinct from airborne and grants protection flat 2.5 when the attacker is airborne.

Check six costs/indices, wrong stat rejection, insufficient input, unchanged undamaged material, repair, extra inputs and MaterialRecipe leftovers. At plan creation, these are required checks, not passing results. Only the coordinator runs builds/server fixtures. No client rendering or full process-restart save migration has been verified.

## Additional differences recorded, outside the first coherent content patch

Original material definitions put blaze and ender_pearl at tier 3 (port 2), blood at tier 2 (port 5), and glowstone/ichor/kobold/magma/quartz at sort 35 (port 25). Gold and rose-gold skull traits have an extra port golden trait. Original source/release modifier differences include entwined movement 0.10 versus 0.15, enderdodging 0.15/0.075 per level versus a flat-plus-level formula, solar_powered `(0.01*level + 0.04)*light` versus `0.05*light`, dragonborn protection 2 versus 2.5, and featherweight movement/use-speed/protection changes. These are verified differences, not automatically authorized broad rebalance edits. Preserve modern body/saddle API support while deciding parity intentionally.

## First implementation boundary

The coherent content patch restores the three original material IDs and their original triplets, acquisition, render info and English names; cuirass/laces traits; required airborn/rugged behavior; original slot selection and doubled ribcage traits; original short-array remapping; and Travelers variable-cuirass crafting and material-value swaps. Existing maille/skull stats and old skin render variants remain. Separate legacy cleaning recipe IDs keep old skin variants cleanable. They keep their serialized IDs and continue using the backing vine material's traits; they are not silently rewritten to standalone skin materials.

The parent reserved unrelated balances for later review. This patch therefore leaves shield factor 22, existing armor attack multipliers and wing durability, other modifier formulas, material tiers and sorting unchanged. Viewer display machinery remains a separate gap; the mechanical recipe exposes its predicate and cost for a future adapter. The original source's successful-shrink false return is corrected: ordinary recipes only match one material stack, but an extra requirement may itself be a valid material. With cost 3 plus extra 1 leather, stacks 5 + 4 should consume 4; the original loop consumes 7 because neither material slot is marked used. The fixture executes the real base loop and includes a false-return negative control.

`local-tests/returning/ARMOR.md` records the ten-case server fixture and its limits. No runtime acceptance is claimed by this document.
